# 部署与事故处置运行手册

## 发布前记录

- 变更负责人、数据库负责人、平台负责人、验收负责人
- 维护窗口、观察窗口、停止时间点和回切决策人
- Git commit SHA、发布清单 digest、镜像 digest
- 目标 API/Web 地址、隔离数据库标识、持久存储标识
- 数据库备份点、文件备份点及联合恢复点编号
- 旧服务版本、旧数据库只读状态和回切入口

任何字段为空时不得切流。

## 部署顺序

1. 冻结写入窗口并保存旧服务健康、版本、错误率与业务基线。
2. 对目标数据库和事实源文件存储建立同一恢复点，完成隔离恢复抽查。
3. 执行迁移 `precheck -> up -> status -> up -> status`，核对账本和 checksum。
4. 部署新 API，但不切流；检查 `/api/health/live` 和 `/api/health/ready`。
5. 执行四角色认证、跨地市拒绝、导入/版本/CAS 409、导出和文件重启复验。
6. 部署 Web 到隔离地址，完成同源浏览器回归。
7. 小流量切换并观察数据库连接、5xx、延迟、认证失败、导入失败和存储错误。
8. 观察窗口通过后才扩大流量；旧服务和旧 schema 保持可回切。

## 立即停止条件

- readiness 非 200、数据库连接耗尽、迁移账本异常或 checksum 漂移
- 事实文件写入后无法读取、hash 不一致、挂载丢失或恢复点不同步
- root_admin 数量不为 1、跨地市访问成功、公开注册恢复或 JWT 无法撤销
- 导入失败覆盖当前有效版本、CAS 冲突未返回 409、冲销数据被拒绝或金额对账漂移
- 持续 5xx、超时、内存增长、任务重复执行或审计缺失

## 故障处置顺序

1. 停止扩大流量；涉及错误写入时立即止写。
2. 保存时间点、请求 ID、版本、账本、应用日志、数据库状态、文件 key/hash 和浏览器证据。
3. 判断故障是否只影响无状态应用。仅应用故障可回切旧镜像；不得自动执行 down migration。
4. 涉及数据库或文件一致性时，保持失败现场只读，从同一恢复点联合恢复到新的隔离资源并对账。
5. 已发布事实通过新版本或冲销纠正，不覆盖历史版本。
6. 修复使用新增迁移或新应用版本；复跑全部门禁后重新安排窗口。

## 常见故障定位

| 现象 | 首查 | 处置 |
|---|---|---|
| live 失败 | 容器进程、端口、启动日志 | 保留日志并回切旧应用 |
| live 成功、ready 失败 | ready 返回的 database/storage 状态 | 隔离依赖故障，不切流 |
| 数据库连接失败 | VPC、白名单、账号权限、连接池 | 禁止切到默认或共享数据库 |
| 存储启动失败 | `/proc/self/mountinfo`、读写权限、挂载标识 | 修复隔离挂载，不使用容器临时目录 |
| 登录失败激增 | JWT_SECRET、auth_version、账号状态、时钟 | 不回退到默认密钥或公开注册 |
| 导入或版本冲突 | 批次状态、错误账本、expectedVersionNo | 保留失败批次，客户端重载后重试 |
| 金额或范围异常 | city scope、版本、来源行、审计 | 止写并按版本/来源对账 |

## 恢复后复验

- live/ready、迁移账本、唯一根账号、四角色权限
- 导入成功/警告/阻断、版本替代链、CAS 409、冲销
- Dashboard/地市/多地市范围与 XLSX 金额对照
- 文件上传、重启、重建、下载和 SHA-256
- 数据库行数、金额、孤儿治理和文件联合恢复一致性

复验未全部通过时，`DEPLOYMENT_GATE=BLOCKED`。
