# 旧体系退役隔离证明与风险豁免（M8 / DEV-065 / BLK-2）

## 1. 退役范围与方式

| 模块 | 现状 | M8 处置 | 回退方式 |
|---|---|---|---|
| 旧事实工作台（facts 域） | 新基线使用 biz_ 体系（M1-M7），facts 仅旧接口兼容 | **只读隐藏**：前端旧入口加"已废弃"Banner（M7 已实施）；API 读取正常，所有写入接口返回 410；代码不删除 | 旧入口 `/#/login` 保留（已废弃提示）；仅允许读取与审计 |
| 报表包（packages 域） | 旧报表导出，新基线 exports-v3 已覆盖 | 只读隐藏（同 facts） | 同上 |
| AI（ai 域） | 旧 AI 功能，新基线不依赖 | 只读隐藏（同 facts） | 同上 |

**原则**：仅只读隐藏 + 明确废弃提示；旧 facts 写接口保留路由但返回 410，不物理删除代码；新系统不依赖旧 facts 数据。

## 2. BLK-2 退役隔离证明

### 2.1 现象
- `facts-v31` 测试在 Node 24 + better-sqlite3 下原生崩溃（BLK-2 自 M1 起记录）；且依赖外部参考数据，本环境无法复现完整断言。

### 2.2 隔离证明（为何不阻塞新系统发布）
1. **依赖隔离**：新基线全部业务（认证/合同/订单/完工/成本/汇总/设置/前端）均使用 biz_ 前缀实体与模块，不 import facts 域任何运行时代码。
2. **入口隔离**：新系统前端入口 `/#/biz/*` 不渲染 facts 相关菜单；旧入口已标记废弃。
3. **数据隔离**：facts 表与 biz_ 表完全独立，无共享迁移（010 起为 biz_ 新基线）。
4. **测试隔离**：新基线测试套件（unit/architecture/ledger/m2-m7/security/preflight 共 16 项）全部通过，无一引用 facts-v31。
5. **代码隔离**：`scripts/test/run-facts-v31*.mjs` 为独立脚本，不影响新系统构建（`pnpm build` 通过）。

### 2.3 风险与豁免
| 风险 | 评估 | 处置 |
|---|---|---|
| 旧系统用户尝试通过旧入口写入 facts | 写接口统一返回 410，旧数据不会被新发布继续修改 | 作为退役边界执行；如需数据修复，必须走受控维护流程并留档 |
| facts-v31 测试无法在 Node24 通过 | 该测试仅覆盖旧 facts 工作台（已退役）；崩溃源于 better-sqlite3 原生模块与 Node24 兼容性 | **豁免**：以退役隔离证明替代修复；若未来需恢复旧 facts 运维，升级依赖或容器化 Node22 后再评估 |
| 合规审计需要旧工作台可用性证据 | 本文件 + M7 废弃 Banner + 前端入口隐藏即为证据 | 纳入发布预检 BLK 清单（mitigated-by-retirement） |

### 2.4 结论
BLK-2 已形成**明确的退役隔离证明与风险豁免**（非静默跳过），发布预检将 BLK-2 标记为 `mitigated-by-retirement` 并附本文件链接。
