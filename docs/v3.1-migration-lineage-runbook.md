# V3.1 迁移与事实文件血缘运行手册

## 安全边界

- 应用启动不执行迁移；生产环境 `DB_SYNC=false`，TypeORM `synchronize=false`。
- 生产迁移必须显式设置 `MIGRATION_APPROVED=true`，并单独执行迁移命令。
- `schema_migrations` 记录迁移版本、文件名、SHA-256、状态、执行方式、耗时与错误。
- 已执行迁移文件不可修改；新增变更必须追加新的 SQL 文件。
- 本手册中的隔离验证不得使用生产数据库主机、数据库名或账号。

## 迁移检查与验证

SQL 文件清单和基础格式检查：

```powershell
pnpm migration-files:check
```

该命令只检查迁移文件清单、命名、顺序和基础格式，不连接 MySQL，不代表 MySQL 兼容验证。

真实 MySQL 隔离验证必须使用具备临时建库、删库权限的非生产账号：

```powershell
$env:NODE_ENV='test'
$env:MIGRATION_TEST_MYSQL_HOST='127.0.0.1'
$env:MIGRATION_TEST_MYSQL_PORT='3306'
$env:MIGRATION_TEST_MYSQL_USER='...'
$env:MIGRATION_TEST_MYSQL_PASSWORD='...'
pnpm test:migrations:mysql
```

脚本要求四个 `MIGRATION_TEST_MYSQL_*` 变量全部显式存在，不回退到 `DB_*`、默认主机、默认端口或默认账号。脚本创建带时间戳和进程号的临时数据库，依次执行 `precheck -> up -> status -> 第二次 up -> status`，断言 001 至 006 迁移账本、历史结构 adopt、005/006 表列与索引、二次执行幂等；另建故障注入临时库，验证失败迁移留下 `failed` 账本和定位信息。成功或失败后删除全部临时库，并从 `information_schema` 确认删除。没有可用的非生产凭据时，该门禁必须标记为阻断，不能用 `migration-files:check` 替代。

生产部署窗口内的迁移命令仅在审批和备份完成后执行：

```powershell
$env:NODE_ENV='production'
$env:DB_SYNC='false'
$env:DB_TYPE='mysql'
$env:DB_HOST='...'
$env:DB_PORT='3306'
$env:DB_USERNAME='...'
$env:DB_PASSWORD='...'
$env:DB_DATABASE='...'

pnpm db:migrate:precheck
pnpm db:migrate:status
$env:MIGRATION_APPROVED='true'
pnpm db:migrate
pnpm db:migrate:status
```

## 隔离集成验证

```powershell
$env:FACT_REFERENCE_ROOT='E:\code2\biz-reporting-design-v2\参考数据'
pnpm test:facts-v31
pnpm test:storage-gate
```

事实数据脚本创建临时 SQLite、原文件目录和随机端口 API，结束时自动停止服务并删除全部临时文件。存储门禁脚本验证生产环境缺少路径、路径错误或缺少真实 Linux 挂载点时都会拒绝启动（该描述为 local driver 回滚路径；当前方案见下节）。

## 原始文件存储（当前方案：私有 COS 对象存储 + 后端 COS SDK 直连）

- **存储驱动**：`FACT_SOURCE_STORAGE_DRIVER=cos`。源文件存于**私有 COS 桶**，API 后端通过 **COS Node.js SDK 直连**（`cos-nodejs-sdk-v5`，唯一允许引用的文件为 `apps/api/src/facts/storage/cos-client.factory.ts`）。
- **MySQL 只保存逻辑 `storageKey`（`xx/<sha256>`）与元数据**（sha256/size/storedAt 等），不存文件正文、不存 COS 完整对象键。
- **CloudRun 无 CFS/COS 文件系统挂载**：运行镜像不创建、不挂载任何本地持久路径；`Dockerfile` 仅声明 `FACT_SOURCE_STORAGE_DRIVER=cos`，凭据经 STS 临时凭据注入（禁止长期密钥入镜像/仓库/日志）。
- 凭据形态：`R1/Q-06 = DECIDED_STS_REQUIRED`；已实现临时凭据形态校验与生产禁永久密钥门禁（`STS_SHAPE_GATE_IMPLEMENTED`）；真实 issuer-backed provider 尚未实现（`STS_REFRESH_PROVIDER_BLOCKED_ISSUER_UNDEFINED`）。
- 文件按 SHA-256 内容寻址：`<前两位>/<64位SHA-256>`，使用独占创建并在重复写入时复验哈希（Local driver 语义；COS driver 走 head-then-put 幂等）。
- 原文件不自动删除，与导入批次同生命周期保留。任何清理策略必须保留审批记录并证明血缘不再需要回查。

> **旧方案/回滚背景（非当前方案）**：历史版本使用本地持久卷/CFS 挂载（`/mnt/fact-source-files`、`com.biz-reporting.required-persistent-mount` 标签、CloudBase 控制台存储挂载门禁、`fuse.cosfs`）。该方案已废弃，仅作为回滚背景保留；**不得**作为当前部署操作步骤执行。回滚到 local driver 时需另行配置本地存储根变量。

## 备份与恢复

- MySQL 备份与 COS 对象备份必须使用同一备份周期、同一保留周期和同一恢复点标识。
- 恢复时先选择同一恢复点，恢复数据库和 COS 对象（按 `storageKey` 内容寻址），再执行批次 SHA-256 抽样回查；任一侧恢复失败或时间点不一致，不得开放导入和原文件下载。
- 备份验收必须同时记录数据库账本版本、COS 桶对象快照标识和恢复演练证据。

## 上线顺序与回滚

1. 冻结迁移 SQL，完成同恢复点的数据库备份和 COS 对象快照。
2. 使用生产同版本的隔离 MySQL 执行 `precheck -> up -> status -> 第二次 up -> status`。
3. 核验私有 COS 桶/Region/prefix 配置与 STS 凭据注入（F 阶段，`BLOCKED_STS_ISSUER_UNDEFINED`），运行存储门禁（local 回滚分支 + cos 分支）。
4. 在生产库只执行 `precheck` 和 `status`，确认无 checksum drift、failed 或 partial 状态。
5. 在批准的部署窗口设置 `MIGRATION_APPROVED=true`，执行一次迁移并再次查询状态。
6. 发布 API，验证上传、下载审计、幂等、失败回查、地市隔离和 Admin 汇总。

回滚不自动删除事实表、血缘列或源文件。应用回退时保留新增表、列和文件证据；迁移失败时先依据 `schema_migrations.error_message` 定位，按同一恢复点恢复数据库与 COS 对象，再追加修复迁移。禁止修改已执行 SQL，禁止在存在事实数据后直接 `DROP TABLE`。**生产实际部署与执行仍需后续发布授权；F 阶段保持 BLOCKED，不得自行创建云资源或部署。**
