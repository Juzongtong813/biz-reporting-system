# 账号与数据范围重构需求

## 目标

将账号的功能权限与数据范围彻底分离，移除运行时对单一 `city_id` 账号绑定和旧的隐式范围推断，使后续新增账号只需配置角色和范围，不需要修改业务代码。

## 用户故事

- 省级账号可以查看全部省份和地市数据。
- 指定省份账号只能查看该省及其地市数据。
- 一个账号可以同时授权多个省份或多个地市。
- 合同管理员保留合同域权限，数据范围按合同对象授权模型处理。
- 超级管理员可以创建账号、配置角色、配置多条数据范围并查看审计记录。
- 新增账号、变更角色或变更范围都不需要新增代码分支。

## 验收标准

1. 当账号拥有 `all` 范围时，系统所有业务查询均返回其权限内的全部省份和地市数据。
2. 当账号拥有一个或多个 `province` 范围时，系统只返回这些省份及其地市数据。
3. 当账号拥有一个或多个 `city` 范围时，系统只返回这些地市数据。
4. 当账号拥有多条范围时，允许范围取并集，越权请求参数只能缩小结果，不能扩大结果。
5. 当账号没有有效范围时，除超级管理员和明确的合同对象权限外，业务数据默认拒绝访问。
6. 当账号执行合同、订单、成本、完工、分析、快照、导入或导出操作时，所有模块使用同一范围解析结果。
7. 当账号角色或范围被修改时，修改结果写入审计日志，并在下一次请求认证上下文加载时生效。
8. 当迁移完成后，运行时不再以 `biz_users.city_id` 作为唯一数据范围来源。
9. 当导入账号范围包含不存在或冲突的省份/地市时，系统在预览阶段拒绝确认，不创建部分账号。
10. 当历史任务保存了旧范围快照时，历史记录仍可读取，新任务使用新的多范围快照格式。

## 范围映射

- “省级，可以看所有” -> 角色 `admin` + `all` 范围。
- “江西看江西” -> 角色 `admin` + `province=江西`。
- “河北看河北” -> 角色 `admin` + `province=河北`。
- 多地市账号 -> 原业务角色 + 多条 `city` 范围。
- 合同管理员 -> `contract_manager` + 合同域对象权限，不依赖单一地市字段。

## 非目标

- 不改变业务权限码的含义。
- 不改变订单、费率、合同金额和快照的计算口径。
- 不在本阶段自动创建生产账号；账号导入需在迁移和预览验证后单独确认。
