# 超级管理员全局数据删除设计

## 接口

新增 `DELETE /biz/admin/data/:resource/:id`，其中 `resource` 是后端枚举，不接受数据库表名。仅 `super_admin` 可调用。

删除结果返回资源类型、目标 ID 和各自有数据表的删除数量。

## 删除边界

删除器使用资源注册表。每个资源实现独立的事务删除函数，按外键所需顺序先删除自有明细，再删除目标记录。

| 资源 | 同步删除的自有数据 |
| --- | --- |
| `order-import-record` | 订单行、导入错误、上传记录 |
| `contract-import-record` | 原始行、工作表、由该记录创建的合同及其分配、费率、预警、上传记录 |
| `contract` | 合同分配、费率、预警、合同记录 |
| `offline-completion` | 线下完工记录 |
| `cost-entry` | 成本记录 |
| `cost-category` | 成本分类 |
| `province` | 省份记录 |
| `city` | 经营单位别名、经营单位记录 |
| `city-alias` | 别名记录 |
| `announcement` | 公告阅读记录、公告记录 |
| `message` | 消息记录 |

跨资源引用不参与删除决策，也不自动删除引用方。删除后调用汇总重算，确保展示数据与数据库一致。

## 前端

增加 `/biz/data-delete`，仅超级管理员可见。页面按资源类型加载可删数据，支持输入记录 ID 精确删除和列表单条删除。每次删除均需要二次确认。

订单上传记录列表中将“作废”替换为“删除”。已作废记录不再显示“恢复”。

## 验证

- 后端回归：订单批次、合同上传记录、合同、成本、线下完工和权限拒绝。
- 前端：超级管理员页面可见、订单按钮文案和确认流程正确、非超级管理员无入口。
- 运行 API 与前端类型检查、构建、订单回归及浏览器验收。
