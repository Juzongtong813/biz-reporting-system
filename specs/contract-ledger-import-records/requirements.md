# 原始合同台账上传记录需求

## 问题与范围

现有合同上传只接受单工作表、自定义字段模板，并会丢弃未映射列。实际台账 `外省(1).xlsx` 包含 3 个工作表；主表 `Sheet2` 为 33 列（含一个空表头列），另有省份统计表和合同编号清单。系统必须直接接受这类原始台账，完整保存可重建数据，同时只把可可靠提取的字段写入现有合同模型。

本变更直接修改现有合同上传入口，不创建平行业务模块；界面使用“上传记录”，内部保留不可变 `importRecordId`。

## 已确认映射

- `甲方合同编号` -> 系统合同编号；`档案室合同编号` -> 辅助合同编号。
- `合同金额（不含税，万元）`、`合同金额（含税，万元）` -> 万元乘以 `1,000,000` 后四舍五入为整数分。
- `税率` -> 原始文本 + 基点数组；单税率同时写入单值基点，复合税率不强行压成一个数。
- `签订日期` -> 签订日期；`合同期限` 起始日 -> 合同开始日；`合同到期时间` 优先作为结束日，无法解析时再取期限结束日。
- `省份` -> 标准省份；受控省级名称未配置时，导入事务自动创建省份字典记录。
- `地市` -> 按省份、标准名、受控别名和明确城市词自动匹配经营单位；多地市不自动分配金额。
- `合同分类-1/-2`、`项目唯一识别编码`、`中标项目名称` 作为必要合同/项目信息标准化。
- 空表头列仍按原列序保存和重建，不擅自命名。

## 保守规则

- `无`、`暂无`、`null`、`-` 等占位合同号不是有效业务键。
- 文件内重复合同号或数据库已存在合同号不覆盖现有合同，来源行标记 `needs_review`。
- 复合地市、标段范围、区县清单不做模糊拆分；原文完整保存，标准经营单位为空且作为非阻断提示。
- 原台账中的税率是税率，不作为合同-经营单位管理费率；导入不得自动伪造管理费率。
- 识别到一个或多个经营单位时创建合同关系，额度统一为 0；管理员补齐额度后才能生效。

## 用户故事

- 作为合同管理员，我可以直接上传实际原始台账，不需要先改成系统模板。
- 作为合同管理员，我可以看到每次上传的文件名、上传时间、上传人、状态和行数统计。
- 作为合同管理员，我可以下载由数据库重建的原始台账，核对工作表、列序和数据内容。
- 作为审计人员，我可以从标准化合同追溯到上传记录、工作表和原始行。

## 验收标准

### R1 完整保存

- 当上传合法 XLSX 时，系统应按原顺序保存所有工作表、使用区域行列数、原始表头、空单元格、单元格基本类型和原始行号。
- 当某工作表不包含合同主表必需表头时，系统应保存其全部数据并标记为辅助表，不创建合同。
- 当上传完成后，系统不得依赖原始 XLSX 二进制文件进行后续下载。

### R2 标准化与异常

- 当主数据行的合同号、名称、省份和含税金额均可可靠解析时，系统应创建草稿合同并记录来源血缘。
- 当关键字段无效、文件内合同号重复或合同号已存在时，系统应保存原始行并标记 `needs_review`，不得覆盖合同。
- 当非关键字段无法可靠解析时，系统应创建合同并将问题记录在来源行，不得阻断同文件其他有效行。
- 当金额单位为万元时，系统应准确换算为整数分，不得先转元后产生浮点累计误差。
- 当日期是 Excel 日期、`YYYY-MM-DD`、点分或斜杠日期时，系统应标准化为日期；`暂无` 等文本保留原值且标准日期为空。

### R3 经营单位与权限

- 当省份属于受控省级字典且尚未配置时，系统应在上传事务中创建省份并复用稳定编码。
- 当省份和地市精确匹配标准名、受控别名或明确城市词时，系统应关联同一经营单位 ID，包括 `province_branch`。
- 当一行包含多个可识别地市时，系统应建立多个经营单位关系，所有额度初始为 0，合同保持待生效。
- 当地市为复合范围或无法精确匹配时，系统不得进行模糊匹配或自动创建经营单位。
- 当账号没有合同上传记录读取权限或全量合同数据范围时，系统应拒绝原始台账重建下载，避免混合省份文件泄露。

### R4 上传记录与追溯

- 当合同管理员查看上传历史时，系统应使用“上传记录”文案并返回不可变 `importRecordId`、文件名、上传人、上传时间、状态、总行数、有效行和待维护行。
- 当标准化合同被创建时，合同应保存来源上传记录、来源工作表、来源原始行和原始行号。
- 当上传、解析、标准化、下载或异常发生时，系统应记录审计日志。

### R5 数据库重建下载

- 当有权限的合同管理员下载某上传记录时，系统应从数据库重建 XLSX，并保持工作表名称与顺序、使用区域行列数、列顺序、空单元格和数据内容。
- 重建下载不要求保留字体、颜色、列宽、边框、合并或冻结窗格。

### R6 发布门禁

- 在用户明确确认“本地测试通过，可以部署”前，系统不得执行 CloudBase 迁移或部署。
- 本地交付前必须通过类型检查、构建、迁移校验、合同台账/权限/下载重建测试和浏览器验收。
