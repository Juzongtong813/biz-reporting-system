## Phase 1：根批次和原始区

- [ ] 4. 设计并评审 source file 与 root batch schema
  - 包含文件 hash、对象存储键、模板签名、operator、city、year、scenario 和状态。
  - 确认幂等键、索引、外键和历史 `import_jobs` 的兼容映射。
  - _Requirement: OP-R2, OP-R3, OP-R10_
- [ ] 5. 建立 batch component 与 raw record 模型
  - 支持合同计划、合同月度、成本、人员驱动和综合代维子数据集。
  - 保留 sheet、row、cell locator、原始值、公式、缓存值和适配器版本。
  - _Requirement: OP-R2, OP-R3_
- [ ] 6. 实现模板注册与版本化适配器
  - 首个适配器识别四张工作表、合并表头和关键字段。
  - 不在适配器内直接调用业务 repository 或发布服务。
  - _Requirement: OP-R3, OP-R4_
- [ ] 7. 建立对象存储迁移和源文件安全策略
  - 新文件只保存 storage key、hash、大小、类型和元数据。

  - _Requirement: OP-R3, OP-R10_

## Phase 2：标准化、映射和质量

- [ ] 8. 实现值状态、单位、期间和数据性质标准化
  - 禁止解析层用默认零覆盖空白或解析失败。
  - 支持实际、预测、假设、派生和截止月份/有效月份数。
  - _Requirement: OP-R4_
- [ ] 9. 建立合同别名与映射工作流
  - 支持组合编码、历史编码、名称差异、地市范围和人工确认。
  - 地市文件对主合同的变更先进入提案或问题，不直接覆盖主数据。
  - _Requirement: OP-R5_
- [ ] 10. 建立跨表对账和质量问题引擎
  - 检查年度合计、月度合计、占位符、孤立行、单位数量级、未知模板和截止期。
  - 输出阻塞/警告级别、来源定位和处置状态。
  - _Requirement: OP-R6_
- [ ] 11. 建立目标标准资产模型
  - 设计合同年度计划、合同月度值、成本月度值、人员驱动、综合代维合同期间快照和指标定义。
  - 明确与现有 `contracts`、`contract_city_allocations`、`report_*` 和 `month_snapshots` 的兼容视图或转接层。
  - _Requirement: OP-R4, OP-R5, OP-R9, OP-R10_

## Phase 3：预览、发布和血缘

- [ ] 12. 实现统一批次预览 API
  - 返回子数据集状态、业务键差异、标准化变化、质量问题和发布影响。
  - 前端不得重新传入批次归属、地市或年度覆盖字段。
  - _Requirement: OP-R2, OP-R6, OP-R7, OP-R8_
- [ ] 13. 实现幂等发布和版本快照
  - 在事务或等价原子边界内写入标准资产、发布版本、快照和血缘。
  - 重复确认返回已有结果；历史版本不可变。
  - _Requirement: OP-R7, OP-R8_
- [ ] 14. 实现撤销、重放和回滚用例
  - 通过新版本或撤销事件处理纠正，不物理删除来源和历史版本。
  - 为失败事务和部分组件失败定义恢复策略。
  - _Requirement: OP-R7, OP-R10_
- [ ] 15. 建立审计和血缘查询
  - 记录 actor、role、city、batch、component、source locator、target version、reason 和结果。
  - 提供从正式指标反查来源文件和从来源记录正查发布版本的接口。
  - _Requirement: OP-R8, OP-R9_
