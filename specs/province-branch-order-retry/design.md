# 省级直属订单与失败批次修正设计

## 总体方案

现有系统大量使用 `city_id` 作为经营数据归属键。为降低风险，本期不进行全量“城市表改经营单位表”重构，而是在 `biz_cities` 增加 `unit_type`，将其语义扩展为经营单位字典：

- `city`：普通地市。
- `province_branch`：省级直属经营单位。

现有合同分配、费率、订单、成本、完工和 RBAC 数据范围继续复用经营单位 ID。前端在需要区分的页面使用“经营单位”文案和类型标签。

## 数据模型

### biz_cities

- 新增 `unit_type varchar(32) not null default 'city'`。
- 写入山东省分公司记录，归属山东省，类型为 `province_branch`。
- `biz_city_aliases` 保存经过确认的精确别名；导入器按“省份 + 标准化别名”解析，不进行模糊匹配。

### biz_order_import_batches

- `source_batch_id`：修正批次来源，可空。
- `batch_purpose`：`normal` 或 `correction`。

### biz_order_rows

- `replaces_order_row_id`：新修正行接替的旧行 ID。
- `resolved_by_batch_id`：旧行被哪个批次接替。
- `resolved_by_user_id`：执行接替的账号。
- `resolved_at`：接替时间。
- `validation_status` 扩展为 `valid | needs_review | superseded`。

原始 34 列始终不可覆盖。修正值写入新订单行，形成可追溯版本链。

## 导入解析

1. 预加载省份、经营单位标准名、经营单位别名、合同、有效分配和费率。
2. 通过省份和精确标准化名称解析经营单位。
3. 校验账号上传时的数据范围。
4. 校验合同、省份、经营单位分配和业务月份费率。
5. 对修正文件额外校验来源批次、来源订单行、原行状态和当前操作人范围。
6. 新批次写入成功后，在同一事务中将来源行标记为 `superseded` 并记录接替关系。
7. 聚合只读取 `validation_status = 'valid'` 且未作废的行，因此旧行不会重复统计。

## 修正文件

文件维持单工作表以兼容现有上传约束。前 34 列保持标准订单模板，尾部增加只用于修正链路的系统列：

- `修正来源批次ID`
- `修正来源订单行ID`
- `原始Excel行号`
- `当前错误原因`

导入器仅将前 34 列作为业务原始值；系统列用于授权和接替校验。普通上传可以不包含这些列。

## API

- `GET /biz/orders/batches/:id/review-export`：导出当前账号可见的待维护行。
- `POST /biz/orders/upload`：保持原接口，增加可选 `sourceBatchId`；文件含修正元数据时创建修正批次。
- 批次详情增加来源批次、用途和接替统计。
- 订单行查询支持 `superseded`，默认全局订单列表不展示已接替行，批次审计详情可查看。

## 权限

- 下载失败数据复用 `operation.order.export`。
- 上传修正批次复用 `operation.order.upload`。
- 后端同时执行功能权限和数据范围校验。
- `super_admin` 为全范围；省级范围包含该省全部经营单位；经营单位范围只包含绑定 ID。

## 前端

- 批次操作增加“下载失败数据”和“上传修正文件”。
- 修正上传入口自动携带来源批次 ID。
- 状态标签增加“已接替”。
- 经营单位选项显示“山东省分公司（省级直属）”。
- 保持现有 Ant Design 高密度工作台风格，不增加独立页面。

## 测试与发布

- 使用隔离 SQLite/MySQL 测试普通地市、省分公司、缺合同、缺分配、缺费率、修正接替、防重和权限越权。
- 本地启动 API 与 Vite，通过 Codex 内置浏览器执行人工验收。
- 发布使用增量迁移；先备份数据库，再迁移、部署后端、部署前端、线上冒烟。
- 迁移只新增字段、索引和种子，回滚代码时保留新增字段；测试批次通过作废退出统计。
